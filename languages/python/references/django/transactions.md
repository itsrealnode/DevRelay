# Транзакции Django

Помести изменения, которые должны стать видимыми вместе, в один `transaction.atomic()` на уровне общей операции. Например, сохрани назначение и историю его выдачи внутри одного блока. При `get_or_create()` добавляй событие создания только при `created=True`, если повтор должен вернуть существующее назначение.

**Конкурентная запись.** Определи точный инвариант. `UniqueConstraint` для пары «наставник + направление» обеспечивает одно назначение на пару. Лимит в три разных направления требует отдельной координации. Один вариант — внутри транзакции блокировать стабильную строку наставника через `select_for_update()` до проверки лимита и записи. Все пути, меняющие этот лимит, должны соблюдать тот же протокол. Проверь поддержку выбранных блокировок на рабочей СУБД.

**После коммита.** Для действия, которое допускает потерю после сохранения, зарегистрируй отправку через `transaction.on_commit()`. Если доставка обязательна, запиши задание на отправку в той же транзакции и предусмотри повторную обработку. Для дублей доставки определи ключ на стороне получателя.

**Проверки.** Вызови сбой между созданием назначения и истории, затем прочитай БД после отката. Проверь отсутствие отправки при откате. Для обязательной доставки смоделируй остановку после коммита до отправки. Конкурентные вызовы запускай через отдельные соединения в реальных транзакциях на той же СУБД, что в рабочей среде. В Django для этого подходит `TransactionTestCase`.
