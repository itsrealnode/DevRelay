# Точки входа Django

Для создания записи через DRF смотри [пример ViewSet, двух сериализаторов и use case](examples/README.md).

Найди ближайшую view и проследи её до модели, менеджера или функции в `services.py`. Разбери HTTP-ввод формой или сериализатором, как принято в модуле. Celery-задача и management-команда разбирают собственные аргументы и вызывают ту же прикладную операцию.

Например, если регистрация заявки создаёт заявку и строку истории, обе точки входа вызывают `register_ticket(...)`. Допустимость перехода проверяет владелец правила внутри этой операции, чтобы прямой вызов из задачи соблюдал те же ограничения. Статус HTTP и ошибки валидации входного формата остаются у view.

Для существующей цепочки `view → services.py → ORM` обычно достаточно моделей и менеджеров проекта. Рассмотри узкий `Protocol`, когда сценарий должен использовать взаимозаменяемые реализации, например два внешних источника рабочего календаря. Опиши только вызов, реально нужный сценарию.

**Проверь** один запрещённый переход прямым вызовом сценария и публичный ответ через view. Для новой второй точки входа проверь, что она правильно передаёт данные и сохраняет общий исход.
