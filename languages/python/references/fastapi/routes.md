# Маршруты FastAPI

Если в проекте пока нет похожего GET-маршрута, смотри [роутер с обработкой отсутствующей записи](examples/router.py) и [схему ответа](examples/schemas.py).

Разбери тело запроса моделью, принятой в проекте. Преобразуй его в аргументы общей операции. Проверяй формат на входе, а допустимость изменения текущего состояния — внутри операции. Отображай предметный отказ в HTTP-статус и публичное тело ошибки на границе API.

**Частичное обновление.** Посмотри, различает ли контракт отсутствие ключа и явный `null`. Например, в Pydantic v2 при поле `display_name: str | None = None` вызов `patch.model_dump(exclude_unset=True)` сохраняет это различие. Для другой версии возьми соответствующий метод проекта. Передай дальше только присутствующие ключи и сохрани явный `None`, если контракт разрешает очистку.

Начни HTTP-проверку с уже заполненного поля. Запрос `{}` должен сохранить значение, а `{"display_name": null}` — очистить его либо получить предусмотренную контрактом ошибку. После каждого запроса прочитай сохранённое состояние.

**Блокирующие вызовы.** Проследи путь до реального драйвера БД или HTTP-клиента. Для асинхронной цепочки используй `async def` и `await`. Для полностью синхронной блокирующей цепочки обычный обработчик `def` выполняется FastAPI в пуле потоков. Если из асинхронного обработчика вызвать синхронную функцию напрямую, она выполняется в потоке обработчика. Учитывай принятый проектом способ работы с этим ресурсом.
