# Зависимости FastAPI

При отсутствии примера регистрации в проекте с Dishka посмотри [провайдер](examples/dishka_provider.py) и [подключение контейнера](examples/demo.py). Провайдер передаёт одну сессию в UoW и репозиторий на время запроса.

Найди точку сборки приложения. Получи клиент или сессию через существующий провайдер, контейнер или `Depends`. В прикладную операцию передавай обычные аргументы. Владельцу ресурса поручи его закрытие при успехе и при исключении. В HTTP-тесте подмени провайдер принятым в проекте способом.

**Когда нужен Protocol.** Посмотри, какие методы вызывает потребитель. Используй существующий контракт, если он подходит. Описывай новый протокол рядом с потребителем или в принятом модуле интерфейсов, когда адаптеры или подмены должны выполнять один контракт. Для вызова одного конкретного класса достаточно его типа.

Например, потребитель вызывает `await titles.find_title(ticket_id=key)`. Его зависимость может выглядеть так:

```python
from typing import Protocol
from uuid import UUID


class TicketTitleReader(Protocol):
    async def find_title(self, *, ticket_id: UUID) -> str | None: ...
```

Объяви возвращаемый тип провайдера как `TicketTitleReader` и верни реальный адаптер. Для проверки подмены укажи такой же ожидаемый тип в месте её сборки. Типизатор проекта проверит асинхронный вызов, именованный аргумент и форму результата. Прогони примеры с существующим и неизвестным ID для обеих реализаций: аннотация сама по себе не обеспечивает одинаковое поведение при отсутствии записи.
