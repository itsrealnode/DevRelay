# Что получает следующая роль

Для небольшой правки достаточно нескольких предложений. Если меняются несколько контрактов, обозначь требования короткими именами или номерами для ссылок в плане и тестах.

| Требование | Текущее поведение | Ожидаемое поведение и критерий |
|---|---|---|
| Повторная выдача направления | В учебном примере второй вызов пытается выполнить ещё одну вставку. Места сверки — функция выдачи и ограничение пары в модели. | Оба вызова возвращают один ID. После второго вызова в хранилище одно назначение. |
| История выдачи | Из постановки неизвестно, должна ли история фиксировать каждую попытку или только первую выдачу. | Уточнить у владельца. Число записей истории станет отдельным критерием после ответа. |

В реальной задаче замени учебные факты ссылками на проверенные места. Передай исходную постановку, существенные ответы пользователя, изменения относительно текущего поведения и открытые вопросы. Ревьюеру и тестировщику нужны исходные слова пользователя для независимой проверки интерпретации.

Если по пути обнаружен старый дефект, укажи, какое требование он затрагивает. Когда связи с задачей нет, не включай его исправление в критерии приёмки.
