# Расхождения и вопросы пользователю

Если в тикете сказано «теперь при повторе отвечаем 200», а тест ожидает 409, опиши смену контракта и связанный тест. Вопрос о статусе уже закрыт самим требованием.

При нескольких допустимых исходах проверь документы, тесты и реальные вызовы. Сформулируй оставшийся вопрос через наблюдаемое действие пользователя или интегратора. Дай варианты, объясни последствия и порекомендуй вариант, если для этого есть основания. Окончательный выбор публичного поведения передай пользователю. Для незатронутой детали сохраняй действующее поведение.

Например, «Сейчас при повторе запись остаётся одна, но отправитель получает 409. Нужно вернуть 200 с прежним ID или сохранить текущий ответ? Рекомендую 200, если повтор должен считаться подтверждённой доставкой». Если реакция отправителя неизвестна, обозначь её как условие. Отдельно проверь, действительно ли хранилище защищено от дубля.

Собери независимые вопросы в одно сообщение. Если ответ на первый меняет необходимость второго, задай второй условно. Покажи, что уже ясно. Имена внутренних классов, выбор фикстур и организацию файлов поручай разработчику.

После ответа зафиксируй принятое решение. Если пользователь ответил только про статус, сохрани остальные вопросы открытыми. Ответ на уточнение сам по себе не разрешает начинать реализацию.
