# Как сверить код с окружением

Начни с потребителя изменения. Для каждой зависимости запиши, что он читает или вызывает, в какой момент и что произойдёт при отсутствии настройки. Проверь условие включения функции, значение по умолчанию и поведение при его использовании.

| Что меняется | Как пройти от кода до запуска |
|---|---|
| URL, токен, флаг, таймаут | Найди имя настройки в коде, затем её источник и привязку к конкретному контейнеру или сервису. Различай аргумент сборки, переменную CI и окружение запущенного процесса. Для `envFrom` проверь имя источника, наличие нужного ключа по доступным декларациям и возможный префикс. |
| Очередь или периодическая задача | Найди издателя, итоговый маршрут и подписки запущенного воркера. Для расписания проверь также, какой процесс его публикует. Имя задачи и имя очереди могут различаться. |
| Зависимость образа, файл или внешний сервис | Проверь финальный образ, команду запуска, путь монтирования или адрес сервиса, который использует потребитель. Используй действующий в проекте способ сборки и доставки. |
| Изменение при выкладке | Если старые и новые процессы пересекаются по времени, установи, в каком порядке доставить конфигурацию, запустить потребителя и включить новый путь. Для изменения формата данных в составе DevRelay Python используй общий справочник по совместимости при выкладке. |

Проследи, какой pipeline выбирает манифест, Helm values, Compose-файл или другой источник для указанного окружения. Учитывай переопределения при сборке итоговой конфигурации. Запись в `.env.example` подтверждает соглашение об имени. Наличие переменной у процесса подтверждай его привязкой. Для внешнего хранилища секретов различай объявленную ссылку и фактическую доступность ключа. Для проверки хватит имён, метаданных или результата штатной операции без вывода значения.

Например, если потребитель уже подписан на очередь, а ключ передан только API, укажи существующий источник и предложи подключить его к потребителю. Если видна только конфигурация staging, ограничь вывод этим окружением. Отдельно укажи, что именно нужно посмотреть в prod, только когда prod входит в задачу.
