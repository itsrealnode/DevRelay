# Выведи кейсы из требований

До чтения diff выпиши из постановки и согласованных решений проверяемые обещания. Для каждого укажи исходные данные, действие и наблюдение, по которому примешь результат. Получай ожидаемое значение независимо от проверяемого кода. Например, для согласованной скидки 10% на сумму 300 ожидай 270. Вызов рабочего калькулятора скидки для вычисления ожидания скроет его ошибку.

После чтения diff добавь достижимые риски реализации. Для каждой новой гипотезы укажи, какое исходное обещание пострадает. Если контракт оставляет два допустимых толкования, задай вопрос о конкретном входе и продолжи проверку определённых сценариев.

Выбери уровень наблюдения. Бизнес-правило можно проверить прямым вызовом. Публичные статусы и сериализацию проверяй через HTTP-клиент приложения. На уровне хранилища используй настоящий механизм записи, когда результат зависит от запросов, ограничений или транзакций.

Опиши кейс через исходное состояние, вход, ожидаемый ответ и ожидаемые изменения. Если есть эффекты, которые при отказе должны отсутствовать, перечисли их. Различай успешный путь, ожидаемый отказ и технический сбой. Выбирай граничные значения вокруг установленного правила. Для максимума в три активных назначения проверь выдачу третьего и попытку выдать четвёртое.

Не перемножай механически роли, поля и статусы. Объединяй случаи только тогда, когда у них общий механизм и один способ обнаружить поломку. Если два поля используют разные преобразования или проверки доступа, у них разные риски. Отмечай, какие варианты исключены условиями постановки.

Затем найди существующие тесты и посмотри на их утверждения. Имя теста «создание прошло успешно» не подтверждает проверку сохранённых полей. К каждому критерию привяжи существующую проверку, новый кейс либо причину, по которой сейчас он недоступен. Если постановка недостаточна, пометь ожидаемый результат как открытый и задай один содержательный вопрос.

Подбери технику под механизм отказа.

| Риск | Как построить различающий кейс |
|---|---|
| Решение зависит от нескольких условий | Составь небольшую таблицу решений. Подбери пары входов, где изменение роли, статуса или флага меняет ожидаемый исход. |
| Переход состояния, повтор, частичный сбой | Выбери последовательность действий над одним объектом. Отдельно проверь состояние между шагами и после последнего действия. Две независимые фикстуры не воспроизведут повтор над уже обработанным объектом. |
| Время или числовая граница | Зафиксируй часы либо исходное число. Проверь сразу до границы, на границе и сразу после неё с точностью, заданной контрактом. |
| Общий ограниченный ресурс | Организуй две попытки с независимыми соединениями по правилам проверки данных. Заранее укажи допустимые исходы для обеих попыток и инвариант для итоговых записей. |
