# Диаграммы DevRelay Python

При прямом вызове верни схему и объяснение пользователю. В полном цикле передай их координатору для показа в текущем диалоге. Работай с кодом в режиме чтения. Для схемы в чате достаточно ответа, файлы создавай по запросу на документацию или изображение.

1. Сформулируй вопрос, на который должна отвечать схема. Определи точку входа, участников и конец интересующего сценария. Если простой ответ исчерпывает вопрос, ответь текстом. Явную просьбу нарисовать схему выполни.
2. Проследи один реальный вызов по коду, тестам и конфигурации проекта. Сверь порядок событий, условия ветвления и последствия для данных. Покажи границу транзакции или асинхронный переход, когда они меняют ответ. Если процесс может выполняться независимо, нарисуй только установленный порядок событий. Например, получение HTTP-ответа клиентом и старт воркера могут происходить в разном порядке.
3. Пометь схему заголовком «Сейчас в коде» или «Предлагаемый вариант». Для предложения назови основание из тикета или плана. При сравнении покажи обе версии отдельно либо покажи схему одной и коротко опиши точную разницу. Сохрани имена реальных состояний. Пробел в сведениях обозначь рядом со схемой и укажи, чем его можно закрыть.
4. Выбери нотацию и способ выдачи по [правилам отрисовки](rules/rendering.md). Проверь каждую значимую стрелку, переход и подпись по их источнику. Под схемой в одном-двух предложениях ответь на исходный вопрос и укажи файлы и символы, по которым можно проверить вывод. Когда исходники недоступны, укажи, что схема построена по описанию.
