# Проверка гипотез

Выбирай гипотезы, которые объясняют имеющиеся факты и дают разные проверяемые прогнозы. Для каждой укажи основание, ожидаемое наблюдение и событие, которое её опровергнет. Выбери проверку, отделяющую наибольшее число версий при малых затратах. Если механизм уже доказан, искусственные альтернативы не нужны.

Например, при зависшей задаче возможны задержка до получения и ошибка между получением и началом обработки. Найди по тому же ID событие получения, затем сопоставь версию воркера и формат аргументов. Если старое тело воспроизводит ошибку на новой версии до вызова бизнес-операции, зафиксируй это отдельно от предположений о времени нахождения в очереди.

Меняй по одному существенному условию. Используй временные данные, контролируемые зависимости и одинаковый вход. Отмечай, что можно подтвердить локально: вызов обработчика не измеряет задержку брокера, успешный мок не подтверждает доставку. Для операций с внешними эффектами используй изолированный контур. При недоступном окружении запроси минимальный недостающий фрагмент с ID и версией или предложи точный замер с двумя ожидаемыми исходами.
